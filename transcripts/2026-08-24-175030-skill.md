  Decisions worth flagging:

  - SkillPage is hand-written, not Spring Data's Page. Serialising Page emits an
    unstable internal shape into a committed TypeScript client.
  - Sorting is fixed in the query (order by lower(s.name)), not exposed as a
    sort parameter — FR-1 names exactly one order, and a sortable column is a
    promise about the schema.
  - Search wildcards are escaped. Without it, search=% returns the whole
    catalogue instead of nothing.
  - Cross-tenant fetch returns 404 with a byte-identical body to an unknown id
    (apart from instance, which just echoes the path). This discharges the
    acceptance criterion TenantScopingIT explicitly deferred to feature 03.

  Two changes outside the module

  GET /api/skills/{id} is the first endpoint with a typed path variable, and it
  exposed two cases where GlobalExceptionHandler fell through to the catch-all
  and returned 500: a malformed UUID, and DELETE on a skill (FR-7's "there is no
  delete"). Both now return 400 and 405. That added one URN,
  ProblemTypes.METHOD_NOT_ALLOWED.

  Not done, deliberately

  - POST/PATCH/activate/deactivate — as you said, later.
  - NFR-2 (cacheable list responses). No cache wired: with no write endpoints
    there is nothing to invalidate it, so it would be dead infrastructure today.
  - No frontend UI. I did regenerate the committed client (step 6 of the module
    checklist) — listSkills, getSkill, SkillPage, SkillResponse — which meant
    rebuilding your running dev backend container.

  One thing to look at

  backend/src/main/resources/db/changelog/modules/skill/002-seed-skills.yaml
  shows as modified in your working tree, but I didn't touch it — it's a
  two-line whitespace-alignment change that looks like an IDE format-on-save. I
  left it alone since it may be intentional. I did verify it's harmless:
  Liquibase normalises whitespace inside sql changesets when checksumming, so a
  rebuilt backend starts clean against the existing database. Worth a glance
  nonetheless, since editing an applied changeset is the one thing
  docs/features/01-seed-data.md warns against.
